### 11.3 P2-26 同指纹重配未刷新 TLS 指纹

根因在 `DeviceRegistry.add()` 的 existing 分支：只更新 `host / port / token / lastSeenAt`，没有更新 `tlsFingerprint`。`DeviceRegistry.all()` 只在 `tlsFingerprint` 非空时调用 `TlsTrust.register()`，因此进程重启后没有信任锚，8443 被当作 HTTP 访问，状态轮询全部失败。

影响：首次安装路径通过；升级用户或已有 registry 条目重配后，冷启会显示“离线”。建议修复：existing 分支同步 `existing.tlsFingerprint = device.tlsFingerprint`（同时刷新 `lastEventAt`），并在 B1 的同指纹重配策略里一并回归。该项列为 **P2-26**，已在 §12 修复（`0.1.0-20261122.1`）。

## 13. 第 13 轮：P3-03 在线待机与 P3-01/02 收口（最终包 `0.1.0-20261123.1`，基线 `0.1.0-20261122.9`）

### 13.1 P3-03 远程暂停后息屏可达

不新增 Service，复用 `CaptureService`：远程暂停时 `pauseByRemote()` 先落 `GuardState.setPaused(true)`，再 `stopCapture(keepStandby=true)`，停采后进入前台待机；`stopSelf()` 只保留给本机停止、过热/低电与存储错误路径。`.9` 进一步增加独立的 `ACTION_STOP_STANDBY`：待机通知的“停止待机”会同时停止 `CaptureService` 与常驻 `LanServerHost`，清除 paused 标记，避免留下“无前台通知但仍响应 HTTP”的幽灵服务。

关键点：

- `stopCapture()` 在停采时 `provider.unbindAll()`，释放 CameraX 的 Preview/VideoCapture，避免“已暂停但相机仍被占用”。
- 待机前台类型从 `camera|microphone` 切换为 `specialUse`（API 34+；API 29–33 为 `dataSync`），Manifest 同步声明 `specialUse` subtype `local_network_standby`；不再向系统虚报相机占用。
- `MainActivity` 在远程暂停时保持预览抑制，`ACTION_EXPORTED` 广播不再因 `!isRunning` 自动恢复预览；`onResume()` 同样检查 `GuardState.isPaused()`。
- 待机通知文案“已暂停 · 设备仍在线，可从本机恢复值守”，并保留 `停止待机` 动作；该动作走 `ACTION_STOP_STANDBY`，同时停前台实例与 `LanServerHost`，用户可完全退出在线待机。
- 顺带修复暂停时 `H264Streamer.stop()` 与分析线程 `publish()/drain()` 的竞态（实测曾触发 `MediaCodec` `IllegalStateException` 进程崩溃）：`publish/stop` 同步化，分析入口在 `!running || stopping` 时直接关闭帧。

| 值守中 | `/api/status`：`mode=guard`、`paused=false`、`charging=false`、`live=false` |
| `POST /api/pause` | `{"ok":true}` |
| 暂停后 | `/api/status`：`mode=idle`、`paused=true`、`live=false`、`frameCached=true`、`watching=0` |
| 前台类型 | `dumpsys activity services`：`isForeground=true`、`foregroundId=1001`、`types=40000000`（specialUse） |

### 13.3 P3-02 `/api/status.live` 语义

`DeviceServer` 三处状态响应统一为：

```kotlin
.put("live", viewers.get() > 0 && LanFrameHub.hasFrame())
.put("frameCached", LanFrameHub.hasFrame())
```

语义变为：`live` 表示“当前有观看端且存在缓存帧”，`frameCached` 表示“存在缓存帧”。`/api/info` 与 `/api/status` 在待机时返回 `live=false, frameCached=true`，避免把“有最近帧”误报为“正在直播”。当前自有观看端不消费 `live` 字段，外部控制台需按新语义适配，文档已在本节标注。

本轮已用观看端真正进入 LiveView 验证正向分支：设备卡点 `(350,480)` 进入实时画面，顶部“已连接”，相机 `/api/status` 返回 `watching=1`、`live=true`、`frameCached=true`（`.9` `bitrateKbps=158`，`.10` `bitrateKbps=74`），不再是只有缓存帧的空直播。证据 `tools\verify\ui-artifacts\p310\p310-live-connected.png`。
