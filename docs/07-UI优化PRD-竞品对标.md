## 1 一页结论

静哨的功能面已经追上开源竞品的合集，但**界面仍然是“功能入口的陈列”**：主界面一排按钮、设置页一列开关、空态只解释“为什么空”。竞品里体验最好的一类（FadCam、lenscast）恰恰相反：**首页只回答一个问题，其余都藏在它该在的地方**。

本文件给出四条不改产品边界的优化主线：

1. **首页从“入口墙”改成“状态卡”**：一眼看到当前模式、运行时长、最近事件、下一步该做什么；其余入口收进“更多”。
2. **设备与画面合并**：设备卡片直接带最近快照与状态时间线，点开即看，不再经过一次“加载中”的空白页。
3. **异常态产品化**：离线、断流、权限缺失、配对失败四类状态各有明确文案、动作与重试路径，不再只弹 Toast。
4. **首次路径三步收口**：“为什么用它 → 放哪里 → 怎么连”，把同意书、走马灯与配对串成一条可退出的流程；其中走马灯文案已承诺“扫码配对”，但观看端尚无扫码能力，需补能力或改文案（v1.1 新增缺口，见 §4.5）。

功能扩展只列与 UI 直接相关的四项（P0 观看端扫码添加；P1 人形检测标注、事件缩略图聚合、多设备网格），其余（云、账号、订阅）明确不做。

## 2 对标范围与方法

### 2.1 对标对象

| 项目 | 定位 | 本次关注的体验点 |
| --- | --- | --- |
| [FadCam](https://github.com/anonfaded/FadCam) | 后台录制器 | 首页模式切换、录制状态常驻、Web UI 远程控制的信息密度 |
| [lenscast](https://github.com/raulshma/lenscast) | 局域网 WiFi 相机 | 浏览器观看页的参数分组、网络质量分级、快捷磁贴 |
| [Retired-Sentinel](https://github.com/Feebami/Retired-Sentinel-App) | 端侧 AI 安防 | 检测框叠加、事件通知的“人/非人”区分 |
| [HomeSentry](https://github.com/obrassard/HomeSentry) | 分布式多机位 | 多机位网格、单机位聚焦、Web 控制台布局 |
| [android-ip-camera](https://github.com/Tea-n-Tech/android-ip-camera) | 局域网推流 | 极简首屏与最小配置路径 |
| AlfredCamera（商业参照） | 双端 App | 扫码配对流程、App Lock、Trust Circle 的人情化表达 |

对标只看**界面与流程**，不复制其架构。竞品的功能事实已在主 PRD §2 记录，本文不重复罗列。

### 2.2 对标方法

- 以“一个从未用过监控 App 的人，从安装到看到画面”为主任务，记录每一步的点击次数与等待时间。
- 以“连续值守 7 天后回看一次事件”为次任务，记录信息是否可被快速定位。
- 只采纳能落到现有单 App 双角色架构内的做法；需要服务端或账号的体验直接排除。

## 3 差距诊断

| 维度 | 竞品做法 | 静哨现状 | 影响 |
| --- | --- | --- | --- |
| 首屏目标 | FadCam 首屏就是一个录制开关 + 状态；lenscast 首屏是画面 + 参数抽屉 | 主界面为预览 + 8 个平级入口（开始/停止、连续记录、黑屏、回看、配对、我的设备、自组网、设置），见 `activity_main.xml` | 新用户不知道该先点哪个；按钮视觉权重相同 |
| 状态表达 | 状态以颜色 + 短句 + 持续时间呈现 | 只有一行 `status_text`，运行时长、分片数、存储余量不展示 | 值守是否真的在跑，缺少可核对证据 |
| 设备发现 | lenscast 用 mDNS + 浏览器地址；Alfred 用扫码 | 已有 mDNS + 手动 IP，但空态只有一个“添加”按钮，手动 IP 入口藏在添加对话框里 | 发现不到时用户不知道还能手输 IP |
| 扫码配对 | Alfred 用扫码完成配对；lenscast 二维码承载地址 | 相机端已用 zxing **生成**二维码（`PairingQr.kt`），观看端**无扫码解码能力**；但走马灯文案已承诺“扫摄像头端的二维码” | 文案承诺了做不到的路径，用户按引导操作会卡在“没有扫码入口” |
| 画面首帧 | HomeSentry 先给最近快照再连流 | 连接前显示“连接中”，无快照兜底 | 弱网下长时间白/黑屏 |
| 事件列表 | Retired-Sentinel 在通知里带检测框 | 时间轴已有缩略图、未读/已锁定筛选与“最近删除”，但同小时事件平铺、无聚合；类型筛选仅 全部/运动/声音（PERSON 类型已产生但未进筛选项） | 一夜几十条事件时回看需逐条滚动；人形事件无法单独筛出 |
| 异常路径 | FadCam 对“进程被杀/存储满”有专门的恢复提示 | 多数异常是 Toast 或一行文字 | 用户不知道下一步动作 |
| 设置组织 | lenscast 按“画面/网络/存储”分组 | 设置页已分组，但开关与说明混排、缺少当前值摘要 | 长页面滚动后找不到关键项 |
| 适配 | HomeSentry 桌面 Web 为主 | 已有 `layout-land` 与 `sw600dp` 双栏；折叠/展开往返已验证不重建播放器（T03971） | ≥840dp（折叠屏展开态）仍只有双栏，无事件侧栏 |

结论：差距不在功能数量，而在**信息层级、状态可信度与异常闭环**。

## 4 UI 优化方案

### 4.1 摄像头端首页：状态卡优先

```text
┌────────────────────────────────────┐
│ 静哨                    摄像头模式  │
│                                    │
│  ┌──────────────────────────────┐  │
│  │  预 览                        │  │
│  │  值守中 · 已运行 03:42:17     │  │
│  └──────────────────────────────┘  │
│                                    │
│  昨晚 22:14 检测到运动 · 已留存     │
│  存储余量 18.2 GB · 保留 7 天       │
│                                    │
│  [ 停止值守 ]        [ 更多 ⋯ ]    │
│                                    │
│  连续记录 · 黑屏记录 · 回看 · 配对  │
└────────────────────────────────────┘
```

规则：

- **一个主按钮**：运行中只显示“停止值守”，空闲时只显示“开始值守”。连续记录与黑屏记录进入“更多”，用底部弹层而非二级页面。
- **状态行必须可核对**：模式、已运行时长、分片数、存储余量四选二常驻，数据来自 `CaptureService` 与 `StorageKeeper`，每 10 秒刷新一次。
- **最近事件一行**：显示最近一条事件的时间、类型与是否已留存；点击直达播放器。
- **次要入口折叠**：保留回看、配对、设备、自组网、设置五个入口，但降为文字按钮或“更多”弹层，不参与主视觉权重竞争。
- **异常优先**：相机被占用、存储不足、通知权限缺失时，状态行替换为阻断色横幅，并给出唯一动作。

验收：

- 新用户从打开 App 到开始值守 ≤ 2 次点击（权限已授予时）。
- 值守中回到首页，3 秒内可说出“是否在录、录了多久、还剩多少空间”。

### 4.2 观看端设备列表：卡片即画面

- 卡片右上角显示**最近快照缩略图**（来自 `/api/snapshot`，失败时回退到设备名首字）。
- 卡片底部一行状态时间线：`在线 · 12 秒前同步`、`离线 · 2 小时前在线`、`告警 · 3 条未读`。
- 状态优先级保持现有 `DeviceState`（`DeviceState.kt`）：告警 > 离线 > 低电 > 过热 > 存储 > 值守中 > 待机，不允许用户排序覆盖。
- 空态分两种：
  - 从未添加：一张三步说明 + “扫码添加”主按钮 + “手动输入 IP”次按钮（手动入口从添加对话框提升到空态可见位置；对话框保留）。
  - 已添加但全部离线：顶部提示“设备可能不在同一网络”，提供“重新扫描”和“检查诊断”。
- 下拉刷新触发一次立即轮询，替代等待 5 秒周期。

### 4.3 实时画面页：先给画面，再给控制

- 首帧前显示**最近一张快照 + 最后在线时间**，而不是全黑加载。
- 断流重连从现状的固定 3 秒重试（`LiveStreamer.RETRY_DELAY_MS`）改为 `1s / 3s / 5s / 10s` 退避，页内显示“第 3 次重连，网络可能不稳定”，并提供“仅看快照”降级开关。
- 画质切换从现状的两档 toggle（自动 / 主码流，`LiveViewActivity.toggleQuality`）扩为底部半透明胶囊三档单选（自动 / 流畅 / 高清，“流畅”复用子码流），切换时不清空当前帧。
- 对讲、警笛、手电三个远程动作统一放右侧竖排图标；触发后按钮变为“停止”，并显示剩余秒数。
- 令牌失效（401）时直接跳到“重新配对”说明页，不在画面页反复重试。

### 4.4 事件时间轴：先看懂，再点开

- 同一小时的事件聚合为一张“小时卡”：最多 3 张缩略图 + 条数；点击展开列表。缩略图数据已存在（`EventStore.COL_THUMBNAIL`，列表已在渲染），本项只做聚合呈现，无新数据依赖。
- 缩略图加载失败用类型图标占位，不阻塞列表。
- 筛选条吸顶，保留现有“全部/运动/声音/未读/已锁定”，新增“有人形”筛选项：`EventType.PERSON` 已在产生（TFLite 已接入），可直接上线，无需占位置灰。
- 删除保留 5 秒撤销条，撤销期间条目半透明且不可再次点击（“最近删除”页保留为第二入口）。

### 4.5 首次路径：三步收口

```text
同意与边界  →  放在哪里（走马灯）  →  连接观看端
   1 页              3 页                  1 页
```

- **同意页**保持现状（合法用途确认 + 系统通知不可关闭说明），不移除、不折叠。
- **走马灯**三页文案已实现（`OnboardingActivity`，与下列内容一致），本次只做交互补强：支持左右滑动翻页（现仅按钮翻页），最后一页直接进入配对引导；可跳过、已看过不重复弹出的逻辑保持现状。
  1. 放稳、对准、接上电源（含“仅充电时值守”的含义）。
  2. 屏幕可以熄灭，通知栏会一直显示采集状态。
  3. 用另一台设备扫码或输入 6 位配对码即可观看。
- **扫码能力缺口（新发现，已决策补能力，P0）**：走马灯与配对页文案均承诺“扫码”，但观看端只有 zxing 生成二维码、无解码能力。已确定方案为**补能力**：在观看端新增扫码页（zxing `decode` + CameraX 预览，复用现有 CAMERA 权限），文案保持不变。
- 配对路径以“扫码 / 6 位配对码 / 手动输入 IP:端口”三选一为验收口径；观看端手动 IP 入口已实现，摄像头端配对页无需重复提供。

### 4.6 视觉与动效

- 维持单一青色强调色；新增**状态色只用于状态**，不用于按钮底色，避免“满屏都在报警”。
- 卡片圆角从现有 16dp 提升到 20dp，卡片间距 12dp → 16dp，提高暗色下的分层可读性。
- 动效只用两种：页面进入 180ms 淡入上移；状态切换 120ms 颜色过渡。禁用循环动画，值守界面不允许持续动效耗电。
- 字号：正文 15sp，状态行 13sp，辅助说明 12sp；支持系统字体放大到 1.3 倍不截断。

### 4.7 适配断点

| 宽度 | 布局 | 变更 |
| --- | --- | --- |
| < 600dp | 单列 | 设备卡单列，实时页全屏 |
| 600–840dp | 双栏 | 左侧设备列表、右侧画面（现有 `sw600dp` 已实现） |
| ≥ 840dp（折叠屏展开/平板横屏） | 双栏 + 事件侧栏 | 新增右侧可收起的事件流，画面保持 16:9 |
| 折叠态 | 单列 | 与手机一致，不因折叠切换而重建播放器 |

## 6 优先级与实施顺序

| 批次 | 内容 | 理由 | 可验证结果 |
| --- | --- | --- | --- |
| 1 | 首页状态卡 + 入口折叠 | 直接影响“能不能放心用” | 首屏点击数与状态可读性验收 |
| 2 | 观看端扫码添加 + 空态分流 | 文案已承诺扫码但能力缺失，是当前唯一的“引导与实现矛盾”（已决策补能力） | 走马灯第三步扫码路径真实走通，三条配对路径均可用 |
| 3 | 观看端卡片快照 | 降低打开等待的空白感 | 卡片可见即有画面或明确状态 |
| 4 | 实时页快照兜底 + 退避重连 | 弱网体验最差的一环 | 断网 30 秒内页面始终有可用画面或明确状态 |
| 5 | 时间轴小时卡 + 人形筛选 | 回看效率；人形筛选无新依赖可随批次交付 | 30 条事件内 10 秒定位目标 |
| 6 | 走马灯滑动补强 | 首次理解成本（三页文案已完成，本批仅交互补强） | 可左右滑动翻页，最后一页直达配对引导 |
| 7 | 折叠屏 ≥840dp 布局 | 设备形态覆盖（折叠/展开往返已验证，本批只做布局扩展） | 展开/折叠不重建播放器 |

每批独立提交、独立可回滚；不一次性重写布局。

## 7 风险与约束

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 首页信息过载 | 状态、事件、存储在首屏堆叠 | 只常驻两条信息，其余进“更多”；按状态动态替换 |
| 快照增加带宽 | 每张卡片周期性取快照 | 缩略图 320px、缓存 60 秒、仅在列表可见时拉取 |
| 动效与省电冲突 | 值守界面长期点亮 | 禁止循环动画；页面不可见即停 |
| 折叠屏兼容 | 布局切换触发 Activity 重建 | 播放器状态存入 ViewModel/单例，重建后自动续流 |
| 走马灯被当成营销页 | 用户快速跳过 | 每页都是可执行信息，提供“跳过”，不阻断 |
| 扫码与隐私披露 | 观看端新增相机预览用于扫码，商店审核关注相机用途 | 仅在扫码页开启预览、退出即释放；隐私政策与商店表单补充“扫码配对”用途说明，不涉及任何图像上传 |
| 三档画质的码流语义 | “流畅/高清”与现有自动/主码流两档语义重叠，切换映射错误会误导用户 | 以子码流/主码流为底层映射写入文案表；切换不清帧、保留当前画面作兜底 |

## 8 验收清单

- [ ] 摄像头端首页在值守/待机/异常三态下，主按钮唯一且文案准确。
- [ ] 观看端空态、离线态、告警态各自有明确下一步动作。
- [ ] 走马灯第三步承诺的配对路径（扫码 / 配对码）在观看端真实可走通；扫码页可用 CameraX 预览并成功解析相机端二维码完成配对。
- [ ] 实时页在断网、令牌失效、设备离线三种情况下均不出现无解释的空白。
