## 2 发布构建流程（未完成项）

`release` 目前只设置了 `isMinifyEnabled = false`，**没有 signingConfig**，因此 `assembleRelease` / `bundleRelease` 产出的包没有可用签名，不能提交 Play。

发布前需要一次构建配置变更（不属于 W25 的代码范围，单独提交）：

1. 生成 upload keystore（建议开启 Play App Signing，本地只保留 upload key）。
2. 把 keystore 路径、别名、口令放入 `~/.gradle/gradle.properties`（不进入仓库）。
3. 在 `app/build.gradle.kts` 的 `release` 中读取上述属性并配置 `signingConfig`。
4. 产出 AAB：`gradlew.bat bundleRelease`；APK 仅用于内测侧载。
5. 上传后 Play 会用 App Signing 重新签名，本地 upload key 丢失可申请重置。

## 4 Data Safety 表单（逐项填写）

| 表单问题 | 填写 | 依据 |
| --- | --- | --- |
| 是否收集或共享用户数据 | 否（No） | 没有服务端；画面、事件、配对令牌均只在用户自己的设备间传输 |
| 数据传输是否加密 | 不适用（未收集数据） | 局域网实时流为明文 HTTP + 令牌，仅在用户可控的家庭网络内使用；详见技术方案 §12.1 |
| 是否使用广告或分析 SDK | 否 | 依赖清单无广告/统计/推送 |
| 是否支持账号创建 | 否 | 无账号体系，配对靠二维码/配对码 |
| 是否允许用户请求删除数据 | 不适用 | 无账号；卸载应用即清除全部本地数据 |
| 是否面向儿童 | 否 | 目标受众为成年家庭用户 |
| 是否包含应用内购买 | 否 | — |
| 照片/视频处理位置 | 设备本地 | `files/clips`、`files/private_gallery`，不进入系统相册媒体索引 |

权限申报与 manifest 已对齐（见 04 文档 §4）：CAMERA、RECORD_AUDIO、POST_NOTIFICATIONS、FOREGROUND_SERVICE（camera|microphone）、INTERNET、ACCESS_NETWORK_STATE、REQUEST_IGNORE_BATTERY_OPTIMIZATIONS、RECEIVE_BOOT_COMPLETED、WRITE_EXTERNAL_STORAGE（≤28）。

## 5 审核说明与演示

- 前台服务用途声明：直接使用 04 文档 §6.1 的英文文案。
- 审核演示步骤：04 文档 §6.2。
- 审核账号：**无需登录**，安装后完成三屏确认即可走完所有功能。
- 建议的演示视频脚本（约 60 秒）：
  1. 首次启动 → 三屏合法用途说明 → 勾选 → 进入首页。
  2. 授权相机/麦克风/通知 → 点“开始值守” → 状态栏出现常驻通知。
  3. 按电源键熄屏 10 秒 → 唤醒 → 从通知点“停止”。
  4. 点“黑屏记录” → 屏幕全黑 → 单击拍照 → 长按退出。
  5. 打开“设置与诊断” → 安全与隐私区展示应用锁、隐私遮罩与审计日志。

## 6 黑屏模式同包策略（确认）

**决策：同包发布，不提供独立“隐形相机”安装包**（PRD O1）。

实现侧已满足该策略：

- 单一 `applicationId`，`BlackScreenActivity` 是同一应用内的普通 Activity，`exported=false`。
- 未设置 `excludeFromRecents`，最近任务与桌面图标正常显示；不做图标伪装。
- 采集期间常驻通知不可关闭，黑屏模式只改变屏幕显示内容，不改变通知可见性。
- 首次启动的合法用途确认与商店文案均显著披露“黑屏时仍在采集”。

禁止事项（避免下架）：不做伪装图标、不做多包矩阵、不在商店文案出现“偷拍/无痕/不被发现”等表述。
